# GETテストケース (2) - 正常系

---

## 前提

- `get_csv_from_jp()` はコメントアウト済みとし、`work/get_inbox/` に手動でCSVを配置して実行する
- DBは実DB（またはテスト用DB）を使用する
- 各テスト実行前にDBの対象レコードを削除し、`work/get_inbox/` / `work/get_progress/` をクリアする

---

## SFTP接続・ダウンロード系

※ `get_csv_from_jp()` のコメントアウトを外して実行する。JP本番SFTP接続が必要。

1. **CSVが1件ある場合、SFTPから取得して get_inbox に保存される**
   - 前提: JPサーバーにCSVが1件存在する状態
   - 操作: `get_csv_from_jp()` を有効にしてバッチ実行
   - 期待: CSVが `get_inbox/` にダウンロードされる / ファイル名・文字コードが正しい / ログに `1 CSV file(s) on JP server` が出力される

2. **CSVが複数件ある場合、全件取得して get_inbox に保存される**
   - 前提: JPサーバーにCSVが複数件存在する状態
   - 操作: `get_csv_from_jp()` を有効にしてバッチ実行
   - 期待: 全CSVが `get_inbox/` にダウンロードされる / 件数がログに出力される

3. **JPサーバーにCSVが存在しない場合、何もせず続行する**
   - 前提: JPサーバーにCSVが存在しない状態
   - 操作: `get_csv_from_jp()` を有効にしてバッチ実行
   - 期待: `get_inbox/` にファイルが追加されない / ログに `No CSV files on JP server.` が出力される / 終了コード0

## 正常系

4. **正常なCSVが1件届いた場合、全件INSERTされる**
   - 前提: 正常なCSV（N行）を `get_inbox/` に配置
   - 操作: バッチ実行
   - 期待: DBにN件INSERTされる / `get_inbox/` からCSVが削除される / 進捗ファイルが削除される / 終了コード0

5. **正常なCSVが複数件届いた場合、全ファイルが順番に処理される**
   - 前提: 正常なCSV（ファイルA・ファイルB）を `get_inbox/` に配置
   - 操作: バッチ実行
   - 期待: ファイル名昇順で処理される / 両ファイルのレコードがDBにINSERTされる / `get_inbox/` が空になる / 進捗ファイルがすべて削除される

6. **get_inbox が空の場合、何もせず正常終了する**
   - 前提: `get_inbox/` にCSVなし
   - 操作: バッチ実行
   - 期待: DBに変化なし / `"No CSV files to process."` がログに出力される / 終了コード0

---

## 重複系

7. **同じCSVを2回実行した場合、2回目は全件スキップされる**
   - 前提: 1回目のバッチ実行済み（N件INSERT済み）、同じCSVを再度 `get_inbox/` に配置
   - 操作: バッチ再実行
   - 期待: DBのレコード数が変化しない / ログに `N duplicate(s) skipped` が出力される / `get_inbox/` からCSVが削除される / 進捗ファイルが削除される

8. **一部重複・一部新規のCSVが届いた場合、新規分のみINSERTされる**
   - 前提: ファイルAを1回実行済み、ファイルAの末尾行を削除したものをファイルBとして配置
   - 操作: バッチ実行
   - 期待: 重複行はスキップ・新規行のみINSERT / ログにスキップ件数と挿入件数が出力される

---

## 大量データ系

9. **20万件のCSVが正常にINSERTされる**
   - 前提: 20万行の正常なCSVを `get_inbox/` に配置
   - 操作: バッチ実行
   - 期待: DBに20万件INSERTされる / チャンク（1,000件×200回）が正しく分割されて処理される / 進捗ファイルが削除される / 終了コード0

10. **20万件のCSVを2回実行した場合、2回目は全件スキップされる**
   - 前提: 1回目のバッチ実行済み（20万件INSERT済み）、同じCSVを再度 `get_inbox/` に配置
   - 操作: バッチ再実行
   - 期待: DBのレコード数が変化しない / 全200チャンクでスキップが記録される / 処理が最後まで完了する

11. **20万件のCSVでチャンク分割が正しく動作する**
   - 前提: 20万行の正常なCSVを `get_inbox/` に配置
   - 操作: バッチ実行
   - 期待: 1,000件ごとにチャンクOKのログが出力される / チャンク境界をまたぐレコードが欠損・重複しない / 全200チャンク完了後に進捗ファイルが削除される

12. **20万件のCSVで処理時間が許容範囲内に収まる**
   - 前提: 20万行の正常なCSVを `get_inbox/` に配置
   - 操作: バッチ実行・処理時間を計測
   - 期待: 許容時間内（目安: 実行スケジュール13:05 → 18:05 の間隔5時間以内）に完了する
